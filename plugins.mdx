title: Plugins
description: Extend Cobalt Backend with supervised HTTP plugin processes.
---

Plugins are trusted external executables that Cobalt starts and supervises. They extend the API under `/plugins/{name}` without recompiling the server.

## Configure a plugin

Add a plugin declaration to your runtime JSON file.

```json
{
  "plugins": [
    {
      "name": "echo",
      "command": "/absolute/path/to/bin/echo-plugin",
      "args": [],
      "auth": "user",
      "startup_timeout": "10s",
      "request_timeout": "30s",
      "config": { "greeting": "Hello" }
    }
  ]
}
```

Build the included Go example with:

```sh
go build -o bin/echo-plugin ./examples/echo-plugin
```

Restart the server after changing plugin configuration. There is no hot reload.

## Plugin contract

At startup, a plugin listens on an ephemeral numeric loopback port and writes exactly one newline-terminated JSON handshake to standard output:

```json
{"protocol":1,"address":"http://127.0.0.1:45678"}
```

The plugin must expose `GET /_cobalt/health`, authenticate the host token, and return `204`. Write logs to standard error; standard output is reserved for the handshake.

The host supplies only these environment variables:

- `COBALT_PLUGIN_NAME`
- `COBALT_PLUGIN_TOKEN`
- `COBALT_PLUGIN_CONFIG`

The host does not pass server database or provider secrets to the plugin.

## Authentication and identity

Set `auth` to `public`, `user`, `admin`, or `api-key`. The host verifies caller credentials before proxying the request. It strips cookies, API-key headers, and caller-supplied `X-Cobalt-User-ID`, replaces `Authorization` with the private plugin token, and supplies a verified user ID in `X-Cobalt-User-ID` when relevant.

The public Go SDK in `pkg/plugin` provides `Serve`, `DecodeConfig`, and `UserID` to implement this protocol.

<Warning>
  Plugins are trusted processes with the operating-system permissions of the server. Process separation is not a security sandbox. Keep credentials plugin-specific and manage them through your deployment configuration.
</Warning>
