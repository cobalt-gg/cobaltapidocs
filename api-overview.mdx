These routes require the configured public host, default `https://api.cobaltlauncher.com`. They are separate from the launcher's internal catalog routes. Use [Catalog and artwork](/catalog) for internal library features.

## API-key management

These three routes require **user** bearer auth, not an API key.

| Endpoint | Input | Response |
| --- | --- | --- |
| `POST /v1/auth/keys` | JSON `{name?:string}` | `201 {key,name,created_at}` |
| `GET /v1/auth/keys` | None | `{data:[{key,name,created_at,last_used_at}]}` |
| `DELETE /v1/auth/keys/{key}` | Full or displayed masked key | `{ok:true}` |

Name is trimmed, defaults to `Unnamed key`, and has a 128-byte maximum. At most 10 active keys per user; more gives 409. Only creation returns the full `cbl_` secret. List masks all but the first eight and last four characters, ordered newest first.

Revoke accepts an unambiguous masked key. If several keys match the same mask, it returns 409 and requires the full key. An absent/already revoked key gives 404. The current authorization code does not update `last_used_at`; do not present it as reliable recent-usage telemetry.

## Versioned game object

```text
{
  id: string,
  name: string,
  slug: string|null,
  release_year: number|null,
  publisher: string|null,
  developer: string|null,
  description: string|null,
  platforms: string[],
  genres: string[],
  rating: number|null
}
```

No `gameId,gameName,price,currentPrice,source` fields are returned in this shape.

## GET /v1/games and GET /v1/games/search

Both require **API-key** auth via `Authorization: Bearer cbl_...` and use the same handler.

Query: `limit` default 20, range 1–100; optional `cursor`, `q`, `platform`, and `genre`. Each text filter is at most 128 bytes, applied with a case-insensitive substring match. All supplied filters combine. Unlike internal discovery search, an empty query lists games.

Returns `{data:VersionedGame[],next_cursor:string|null}`, ordered by game ID. Pass `next_cursor` as the next request's `cursor`, retaining filters. Null means no more matches. There is no total count.

## POST /v1/games/bulk

**API key.** JSON `{ids?:string[],names?:string[]}`, 1–100 combined. Returns `{data:VersionedGame[],missing:string[]}`. Same lookup/deduplication rules as internal bulk; no count field.

## GET /v1/games/{id}

**API key.** Resolves ID, slug, or normalized name/alias. Returns one VersionedGame directly or 404.

## GET /v1/games/{id}/stats

**API key.** Returns `{game_id,total_players,total_playtime_seconds,total_sessions}`. Values aggregate recorded Cobalt playtime totals; “players” counts user/game total rows, not currently online players or worldwide owners.

## GET /v1/games/{id}/prices

**API key.** Returns `{game_id,data:[{store,price,regular,cut,expires_at}]}`. Price and regular are stored strings; values and expiry can be null. It is stored sale data, not a live multi-store pricing query.

## GET /v1/stores

**Public.** Returns `{data:[{id,name,url}]}`. Fixed IDs are `steam,gog,epic,xbox,playstation,nintendo`. Listing a store does not guarantee an active integration for that store.

## Registered placeholders

All require **API-key** auth and return `501 {"error":"this data source is not configured"}`:

- `GET /v1/games/{id}/achievements`
- `GET /v1/games/{id}/achievements/{achId}`
- `GET /v1/games/{id}/reviews`
- `GET /v1/games/{id}/reviews/summary`
- `GET /v1/games/{id}/news`
- `GET /v1/games/{id}/patches`

Do not present these as working app capabilities.
