---
title: Deploy and operate
description: Roll out Cobalt Backend safely with database migrations and health checks.
---

Use the repository Dockerfile and `render.yaml` as the baseline deployment definition. The image contains `cwebp`, which the artwork pipeline requires.

## Before the first rollout

1. Back up the production database.
2. Stop the previous backend writer before applying replacement migrations.
3. Set all required identity and database variables in the deployment platform, never in Git.
4. Configure `http.app_host` and `http.public_host` for the production domains.
5. Configure your reverse proxy's immediate CIDR ranges before trusting forwarded client IPs.

<Warning>
  Do not run legacy and replacement backend writers against the same database concurrently. The historical schema remains compatible, but concurrent writers undermine a controlled migration.
</Warning>

## Migrations

The server runs idempotent migrations at startup by default. For a large existing database, run migrations separately near the database first:

```sh
go build -o bin/db-migrate ./cmd/db-migrate
./bin/db-migrate -timeout 30m
```

Use `./bin/db-migrate -check` to report source row counts without modifying the database.

The migration utility requires only `DATABASE_URL` and, when applicable, `DATABASE_DIALECT`.

## Health checks

| Endpoint | Meaning |
| --- | --- |
| `/livez` | The HTTP process is alive. It does not require a configured host. |
| `/readyz` | Startup completed, database access works, and required plugins are healthy. |
| `/health` | Historical application health route; requires `http.app_host`. |
| `/v1/health` | Public API health route; requires `http.public_host`. |

Use `/readyz` for deployment readiness checks. It returns `503` until the service can safely accept traffic.

## Supabase production guidance

Cobalt accesses PostgreSQL directly and enforces authorization in Go. Its tables contain private account and message data and do not include Supabase Row Level Security policies.

Disable the Supabase Data API for the Cobalt database, or use a separate project for data exposed through that API. Keep the legacy service-role JWT exclusively on the server.

## Shutdown and observability

The service emits structured JSON logs. Request logs record route patterns rather than query strings, helping prevent tokens, OAuth codes, and search text from entering logs.

On shutdown, the server stops accepting new requests, drains workers, closes WebSocket clients, and stops plugins within the configured `http.shutdown_timeout`. A required plugin exit makes the server stop so your process supervisor can restart it.
