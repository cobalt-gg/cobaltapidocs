Use this reference when changing the launcher, Cobalt ID, or another Cobalt client. It explains which requests to send, the exact field names to read, and the behavior your app must handle.

The contracts describe the active Cobalt Backend checkout reviewed on September 13, 2026, at revision `2ebf4c8c6923286ebee5192c9a3fcc1ae37c4a25`. They are implementation-derived, not a claim that every deployment already runs that revision. Cobalt ID was checked as a consumer of these contracts.

## Boundaries to preserve

The backend owns identity verification, authorization, persistence, provider credentials, catalog enrichment, and upload storage. Clients own interface state, local files, DM encryption, save conflict decisions, and browser handoff verification.

Do not invent an endpoint because a UI feature needs one. For example, there is no registered password-recovery completion route separate from the password-change route, no Minecraft unlink route, and no HTTP endpoint for removing a passkey. Existing constraints and unavailable flows are called out where they affect app behavior.

This reference covers the built-in application routes. Deployment procedures and external plugin authoring are outside its scope.
