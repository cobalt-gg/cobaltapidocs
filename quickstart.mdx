title: Run locally
description: Start Cobalt Backend against a local database.
---

Use this guide to start the server with PostgreSQL and Supabase Auth. The service requires Go 1.23 or later.

## Before you begin

You need:

- Go 1.23 or later.
- A PostgreSQL database. PostgreSQL 16 is a good local default.
- A Supabase project and its project URL, publishable key, and legacy `service_role` JWT. Firebase is also supported for existing deployments.

## Configure the environment

From the backend repository, copy the example environment file and replace its placeholder values.

```sh
cp .env.example .env
```

The process deliberately does not load `.env` files itself. Export the values in your shell or load them through your development environment.

```sh
export DATABASE_DIALECT=postgres
export DATABASE_URL='postgres://cobalt:password@localhost:5432/cobalt?sslmode=disable'
export AUTH_PROVIDER=supabase
export SUPABASE_URL='https://YOUR_PROJECT.supabase.co'
export SUPABASE_PUBLISHABLE_KEY='YOUR_PUBLISHABLE_KEY'
export SUPABASE_SERVICE_ROLE_KEY='YOUR_LEGACY_SERVICE_ROLE_JWT'
```

The service-role JWT is server-only. Never put it in a desktop client, web client, or source control.

## Validate and run

Build the server, validate the configuration, then start it.

```sh
go build -o bin/cobalt ./cmd/server
./bin/cobalt -check-config
./bin/cobalt
```

The server applies idempotent schema migrations during startup unless you disable `database.migrate` in the runtime configuration.

## Check the service

`/livez` reports whether the process is running. `/readyz` also checks database access and required plugins.

```sh
curl http://localhost:8080/livez
curl http://localhost:8080/readyz
```

For local requests to host-restricted routes, set the appropriate `Host` header or change `http.app_host` and `http.public_host` in your local runtime configuration.
