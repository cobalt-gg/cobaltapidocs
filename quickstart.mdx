## Restore an app session

1. Load your stored access and refresh credentials.
2. Request `GET /auth/profile` with the access token.
3. On `401`, run one shared `POST /auth/refresh` request for concurrent callers.
4. Store the rotated tokens and retry each failed authenticated request once.
5. If authorization still fails, clear the local session and return to sign-in. Treat network failure separately from invalid credentials.

The existing Cobalt ID client uses local storage key `cobalt-id-session` for `uid, email, idToken, refreshToken` and rereads the profile. Its `signOut()` clears local state only. Ending a remote device session requires the sessions API.

## Register and finish a profile

Fetch `GET /auth/policy`, then submit `POST /auth/sign-up`. If it returns `201` with tokens, adopt the session. If it returns `202 confirmationRequired`, collect the email code and use `POST /auth/verify-code`.

Confirmation-enabled sign-up does not reserve or persist the requested profile fields. After verified sign-in, patch `/auth/profile` with the chosen display name and username; handle a username conflict then. See [Authentication](/authentication).

## Build a profile game picker

1. Call `GET /search?q=...&limit=8` without authentication for discovery results.
2. Read `gameId` and `name`; discovery fields differ from the catalog's `gameName`.
3. Call `POST /art/bulk` with `{"gameIds":["..."],"types":["portrait"]}`.
4. Use cached URLs, show placeholders for queued/missing art, and poll queued entries with backoff.
5. Save the complete replacement `showcaseGames` array using `PATCH /auth/profile`. Each item conventionally contains `id, name, coverUrl`.

## Open account management from the launcher

Call authenticated `POST /auth/portal-token`, optionally including `refreshToken`. Open its `url` in the browser. The portal reads the query token, exchanges it through `POST /auth/portal-session`, and removes it from the address bar.

The link expires after two minutes and can be used once. Minting a new portal link invalidates older portal links for that user. See [Browser authentication](/browser-auth).

## Keep messages synchronized

Connect the [WebSocket](/messages), reconcile through `GET /social/dm/sync`, and merge messages by `id`. Persist `nextCursor` after applying a page; continue while `hasMore` is true. Apply `message` and `message_update` events to the same local store. Reconnect with backoff and resync after every gap.

The synchronization API reports current message records, including edits and tombstones. It is not an event log, and cannot recover every intermediate state. Preserve local deduplication and tolerate repeated updates.

## Synchronize a save

Read effective `GET /settings/{gameId}` and metadata from `GET /saves/{gameId}`. Compare local and cloud timestamps and apply the chosen conflict policy in the client. Download cloud bytes or upload local bytes after deciding.

The backend stores the settings but does not enforce them during upload. Uploading an older file can overwrite a newer cloud save. There is no conditional-write token or version history. See [Cloud saves](/saves).

## Track a play session

Generate one stable `session.id` at game launch. Periodically send `POST /sync` with the same ID, cumulative session duration, and your cumulative lifetime total for that game. Reconcile your local total with `GET /totals/{gameId}` before sending a later value.

The backend takes the maximum reported total; it does not add each device's total. See [Playtime](/playtime).

## Before changing a client contract

Verify the endpoint's auth label, wire field casing, response envelope, and non-200 success states. Use the feature's existing identifiers; a Steam app ID, Cobalt game ID, Game Pass product ID, profile username, and user UID are not interchangeable.

For UI-only changes, keep requests unchanged. For a new interaction, use an existing documented route and account for its side effects. Do not silently assume a missing backend capability.
